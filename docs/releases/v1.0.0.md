# KIDE 1.0.0 Release Notes

KIDE 1.0.0 establishes the first production-ready baseline for knowledge-integrated systems engineering.

The release combines browser-side deterministic synthesis, qualification and release evidence with self-hosted authentication/persistence and a provenance-aware device knowledge fabric.

## Release highlights

- deterministic synthesis remains entirely in browser TypeScript;
- generated control models are independently re-parsed and validated;
- approved control models generate deterministic ROS 2 Python, IEC 61131-3 Structured Text and Zetta Node.js target artifacts;
- target code carries SHA-256 provenance and is included in the checksummed release manifest;
- qualification and assurance evidence is packaged into checksummed release bundles;
- Better Auth + PostgreSQL provide self-hosted identity and persistence;
- Cloud Run + Cloud SQL deployment fails closed when production auth is not operational;
- JanusGraph and ArcadeDB semantic projections are parity-tested;
- trusted global device knowledge carries provenance, confidence and contract completeness;
- graph-assisted synthesis is guarded by shadow qualification, default-off flags, a runtime production policy and a kill switch;
- graph snapshot drift invalidates approvals before release;
- production launch requires preflight, backup/PITR, live smoke testing and machine-readable acceptance evidence.

## Important limitation

KIDE 1.0.0 does not synthesize executable commands from graph-only device metadata. Executable control generation remains grounded in validated project models. ROS 2 generation uses a documented std_msgs/String JSON transport boundary because the current interface DSL does not declare ROS custom message types; device-specific middleware bindings remain the responsibility of the deployment adapter. This is a deliberate safety boundary.

## Before publishing the release

Do not publish the final release tag until:

1. current `main` CI is green;
2. the production restore drill is completed;
3. production launch preflight passes;
4. live smoke passes against the deployed production origin;
5. launch acceptance evidence verifies;
6. the tag SHA exactly matches the acceptance evidence `commitSha`.
